# ORANOS — LOVABLE VISUAL ACCEPTANCE CHECKLIST

## 5-second test
The homepage must communicate:
- ORANOS has a distinct identity
- ORANOS is a world/community, not a generic gym website
- OTERNAL, Titan, and Community are meaningful experiences inside ORANOS

## Visual rejection conditions
Reject when it resembles a generic black/gold luxury template, AI SaaS landing page, generic fitness startup, crypto/cyberpunk interface, generic Apple clone, or stock-photo collage.

Reject if:
- every section is a centered card grid
- every CTA has an arrow
- gold is everywhere
- blue is neon decoration only
- typography is inconsistent
- mobile feels like squeezed desktop
- sections have no visual relationship

## Product acceptance
Homepage → OTERNAL → explanation → Enter → authentication → external app
Homepage → Titan → explanation → Apply → authentication → My ORANOS → workflow
Homepage → Community → explanation → Join/Enter → authentication → member environment

## Responsive acceptance
Check 360, 390, 412, 768, 1024, and 1280+.
No horizontal overflow.
No clipped text.
No broken buttons.
No unusable navigation.
No giant dead zones.

## Content acceptance
No invented member counts, testimonials, awards, statistics, screenshots, or unsupported claims.

## Integration acceptance
After Lovable output is integrated:
- existing Supabase logic still works
- Titan workflow still works
- manual Titan Pass issuance remains manual
- auth callbacks work
- OTERNAL remains separate
- production remains untouched until explicit release approval
